## R101 — Future-24 implementation reachability and production-studio state reconstruction

**Review completed before correction.** The complete File 10 package was traversed against F10-FR-001..019, F10-NFR-001..010 and F10-FUT-001..024. Future REST routes, production-source/scene/guest/config/simulcast persistence, progressive frontend, object authorization, opaque-ID boundaries, provider-readiness rules and the P0 multi-camera/guest/simulcast/health requirements were reviewed together.

**Frozen finding:** File 10 had canonical mutation paths for production sources, scenes, guest delegation, live policy and simulcast targets, but no owner-scoped canonical read path capable of reconstructing that production state after a reload. The `vwlb_future_production_studio` shortcode also rendered only a capability statement rather than current state. The result was a real end-to-end completeness gap: persisted File 10 production state existed but a broadcaster could not reload it through the versioned opaque-ID REST contract without direct database knowledge.

**Correction:** added `GET /live-events/{id}/production/state` to the canonical Future REST surface. It rechecks the live-event object capability, returns private/no-store data, fails closed with 503 when DB state cannot be verified, excludes native integer IDs/user IDs/credential references, maps scene source membership to opaque public source IDs, and returns safe current sources/scenes/guests/config/simulcast state. The production-studio shortcode now binds to an authorized live event and progressive JavaScript renders current state rather than claiming unconditional provider readiness.

**Regression gate:** `tests/file10-r101-r120-contracts.sh` establishes the R101 read-surface, opaque-ID and UI-state contracts in addition to the complete existing suite.
