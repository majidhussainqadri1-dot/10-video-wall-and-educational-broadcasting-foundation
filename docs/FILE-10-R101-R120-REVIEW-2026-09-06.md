## R102 — Authorization, opaque identifiers and IDOR boundary

**Review completed before correction.** Core, extended and Future REST route registration, command-service authorization, File 10 repository lookup semantics, Future `public_row()` lookup, moderation target resolution, media/video/live/podcast foreign-key inputs and public DTOs were reviewed together from the R101-green exact head.

**Frozen findings:** (1) public REST path regexes accepted all-digit values while `VWLB_Repository::find()` and Future `public_row()` deliberately interpret numeric strings as native primary keys, so public callers could address File 10 records by database ID instead of the required opaque identifier; (2) several public mutation bodies accepted native foreign keys (`channel_id`, `asset_id`, `video_ids`, replay `video_id`, podcast/series/caption IDs, download `object_id`, attachment IDs and media `source_object_id`); (3) caption and podcast creation/public episode DTOs leaked native numeric IDs; and (4) the playback REST enrichment tried to read an internal `id` from the already-redacted public video DTO, so chapters and auxiliary media tracks were looked up with object ID zero.

**Correction:** File 10 now has a single opaque-public-ID syntax guard; all REST object path identifiers require prefixed opaque IDs; public foreign references are resolved to native keys only inside the REST boundary; raw/internal ID fields are rejected; attachment references require an external public-reference resolver; moderation uses `target_public_id`; podcast/caption public DTOs no longer disclose native IDs; generic media initiation cannot accept caller-controlled native source linkage; playback enrichment re-resolves the authorized video internally before loading chapters/tracks; and the root release identity/status was aligned to the corrected candidate.

**Regression gate:** `tests/file10-r101-r120-contracts.sh` asserts route public-ID syntax, public foreign-reference names, DTO redaction and the playback internal re-resolution contract. Historical route/version assertions were rebased to the current opaque-ID/release contract without weakening their substantive gates.

**Retest:** exact-head File 10 Release QA run `34064117765` completed successfully on PHP 8.3 and 8.4 at reviewed HEAD `895c2d66a35a7b9430379a8eff8bc65aaf2d340c`; complete suite, R101–R120 gate, deterministic `1.2.13-rc1` package, checksum/archive verification, package/source parity and artifact publication were green before R103 began.

## R103 — Schema/migration completeness and non-REST canonical-ID boundary

**Review completed before correction.** Starting only after the R102 exact-head green gate, the activation/reconciliation path, base/extension/Future installers, release schema guard, diagnostics/repair surface, legacy SVW migration, repository lookup semantics, canonical frontend rewrite routes, podcast public read path and destructive-uninstall containment were reviewed together against the File 10 migration/rollback, no-silent-data-loss and public-opaque-ID laws. Baseline exact HEAD: `895c2d66a35a7b9430379a8eff8bc65aaf2d340c`.

**Frozen findings:**
1. Partial schema drift could be falsely accepted because the migration verifier proved table existence but not all required columns/indexes before version markers were trusted.
2. Legacy migration read at most 10,000 rows and then marked itself complete, creating a silent truncation boundary for larger legacy datasets.
3. Canonical frontend `/video/`, `/live/` and `/podcast/` routes still admitted numeric/native IDs even after R102 closed the REST boundary.
4. `VWLB_Podcasts::public_episode_dto()` could dereference an undefined `$wpdb` while projecting a series public ID.

**Correction:** schema verification was strengthened to inspect required columns/indexes before schema markers are trusted; legacy migration was converted to bounded checkpointed 500-row progression without a silent 10,000-row completion boundary; frontend rewrite/query/shortcode paths now require opaque public IDs; podcast projection declares and safely uses the database handle; and the Video Wall thumbnail path was aligned to the public thumbnail DTO rather than a native attachment ID.

**Regression gate:** R103 contracts assert schema structural proof, checkpointed legacy migration, non-REST opaque-ID enforcement, podcast safe projection and public thumbnail consumption.

**Retest:** exact-head File 10 Release QA run `34064836972` completed successfully on PHP 8.3 and 8.4 at reviewed HEAD `e0a7ae7efba4c2287dc57c3978e4ef9953ef3aa3`; complete suite, deterministic `1.2.14-rc1` package, checksum/archive verification, package/source parity and artifact publication were green before R104 began.
