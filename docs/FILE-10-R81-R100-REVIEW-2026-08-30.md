**Review completed before correction.** The recursive repository tree, canonical package builder, README/runtime identity, and the historical `video-wall/` source were reviewed together.

**Frozen finding:** the repository still contained an independently activatable WordPress plugin entrypoint at `video-wall/video-wall.php`. The historical source remains repository history only; the canonical runtime/package remains `video-wall-and-live-broadcasting`.

**Regression gate:** `tests/file10-r81-r100-contracts.sh` asserts the canonical entrypoint, inert legacy archive marker and canonical package source.

## R84 — Forensic watermark policy/session grant audit

**Review completed before correction.** The F10-FUT-023 watermark policy table, policy-management command, REST grant route, R79 viewer-session guard and final watermark payload generator were reviewed as one authorization/delivery path.

**Frozen finding:** R79 first read the watermark policy with explicit DB-error handling and verified the viewer session for forensic/both mode, but then called `VWLB_Future_Intelligence::watermark_payload()`, which independently re-read the policy without checking `$wpdb->last_error`. A DB failure or transient policy-read failure in that second query could therefore be interpreted as “no policy” and return `mode=off`, silently downgrading a forensic watermark grant after the first policy read had already established that watermarking was required.

**Correction:** the R79 guard now includes the policy version in its verified snapshot and constructs the grant from that same snapshot. It no longer performs the second unverified policy query. Forensic audit evidence remains bound to the verified policy version and viewer-session reference.

**Regression gate:** the R81–R100 contract now requires the verified policy snapshot/grant helper and forbids the previous `watermark_payload(array('mode'=>'off')...)` re-query path.

**Retest:** pending exact-head File 10 Release QA before R85.
