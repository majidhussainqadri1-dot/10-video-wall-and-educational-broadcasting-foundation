## R84 — Forensic watermark policy/session grant audit

**Review completed before correction.** The F10-FUT-023 watermark policy table, policy-management command, REST grant route, R79 viewer-session guard and final watermark payload generator were reviewed as one authorization/delivery path.

**Frozen finding:** R79 first read the watermark policy with explicit DB-error handling and verified the viewer session for forensic/both mode, but then called `VWLB_Future_Intelligence::watermark_payload()`, which independently re-read the policy without checking `$wpdb->last_error`. A DB failure or transient policy-read failure in that second query could therefore be interpreted as “no policy” and return `mode=off`, silently downgrading a forensic watermark grant after the first policy read had already established that watermarking was required.

**Correction:** the R79 guard now includes the policy version in its verified snapshot and constructs the grant from that same snapshot. It no longer performs the second unverified policy query. Forensic audit evidence remains bound to the verified policy version and viewer-session reference.

**Regression gate:** the R81–R100 contract now requires the verified policy snapshot/grant helper and forbids the previous `watermark_payload(array('mode'=>'off')...)` re-query path.

**Retest:** exact-head File 10 Release QA run `33293933489` completed successfully for PHP 8.3/8.4, full suite, package build, checksum/archive and source/package parity before R85.

## R85 — Recording-consent and recording-finalization lifecycle

**Review completed before correction.** The live-event state machine, normal/end and emergency-end paths, durable recording-job creation, processing worker, extension recording-consent command/gate, R73 version-bound consent proof and replay publication path were reviewed together against F10-FR-012/F10-FR-015, CV-114 and AJ-16.

**Frozen findings:**

1. A recorded live event was moved to `ended` and a finalization job was inserted, but the canonical live event was never advanced to the already-defined `recording_processing` state. Successful job completion likewise did not advance the event to `replay_review`, and a dead finalization job did not advance it to `failed`. The job queue and canonical live lifecycle could therefore disagree indefinitely.
2. The R73 consent proof was registered as an early `vwlb_finalize_live_recording` filter. A later provider/finalizer filter could replace an earlier consent `WP_Error` with success, so consent was not guaranteed to be the final fail-closed veto after actual recording finalization.
3. R73 returned the incoming finalizer result when the referenced live event was genuinely missing. A successful provider finalization could therefore be marked complete even though the canonical event needed for consent/lifecycle proof no longer existed.
4. Recording finalization used the live event's current recording policy rather than a policy snapshot bound to the queued job. The policy/consent version governing the recording was therefore not durably tied to the finalization attempt.

**Correction:** all four findings were corrected as one batch after the review freeze. Recording-enabled end/emergency-end now queues the finalization job with a recording-policy/consent-version snapshot and moves the canonical event atomically into `recording_processing`; successful finalization locks the canonical event, applies the final consent proof after the provider/finalizer result, and advances to `replay_review` in the same transaction as job completion; terminal finalization failure advances the canonical event to `failed`; missing/unreadable canonical live state fails closed. Permanent R85 regression gates were added to `tests/file10-r81-r100-contracts.sh`.

**Retest:** source-correction exact head `fd982736c5a73960e5df9b32463fe499b57a974b` passed File 10 Release QA run `33294397908` for PHP 8.3/8.4, full suite, package, checksum/archive and source/package parity. Adding the permanent R85 contract initially exposed one stale test expectation in run `33297711497`: the assertion incorrectly allowed a direct `recording_processing → replay_published` transition even though the corrected lifecycle deliberately requires `replay_review` first. The assertion was corrected within the R85 retest boundary, not as a new review finding. Final exact-head R85 retest at `3572f9306ac8e9b726c30ce7c609a9db48b1834b`, run `33297818558`, completed successfully. ## R86 — Provider health and live-reconciliation persistence truth

**Review completed before correction.** Provider registration/exception wrapping, provider-health circuit state, processing-provider availability, live-provider reconciliation, repository versioned persistence, and operational failure signalling were reviewed together.

**Frozen findings:**

1. `VWLB_Observability::record_provider()` read the existing provider-health row without clearing/checking `$wpdb->last_error`. A failed health-history read could therefore be treated as an absent first-use row and a later successful `REPLACE` could reset accumulated failure/circuit state instead of failing closed.
2. The live reconciliation worker ignored the result of `VWLB_Repository::update_versioned()` when persisting reconciled provider state. A version/DB persistence failure could therefore discard the reconciliation result without an operational failure signal, weakening the required reconciliation/degraded-provider evidence trail.

**Correction:** both findings were corrected together after the R86 freeze. Provider-health recording now clears and verifies the history read before calculating failure/circuit state and emits `vwlb_provider_health_history_read_failed` instead of rewriting state when the history cannot be trusted; provider availability also starts from a clean DB-error state. Live reconciliation now checks the versioned provider-state persistence result and emits `vwlb_live_reconcile_persist_failed` with an opaque live reference and error code when persistence fails. Permanent R86 regression gates were added.

**Retest:** exact-head correction/test HEAD `b3f0ea3cd5d22c6624ec99ec4b41875d312a77eb` passed File 10 Release QA run `33298112294` successfully, including PHP 8.3/8.4 complete suite, canonical package, checksum/archive and source/package parity. R87 may start after this green boundary.
